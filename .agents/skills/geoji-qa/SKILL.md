# 떼거지 QA 하네스

TC를 받아 화면마다 코드 대조와 브라우저 실행을 돌리고 TC 번호마다 판정을 낸다. 코드는 고치지 않는다.

## 입력

- TC. `docs/release/TC.md`. 없거나 명세가 바뀐 뒤면 `tc-author`를 먼저 불러 만들거나 맞춘다
- 대상. dev 서버 포트 3800. 배포 주소는 서버를 못 불러 대상이 아니다(`docs/product/ROADMAP.md` 미결정 절)
- 명세 정본. `docs/design/DESIGN-SPEC.md`, `docs/product/SPEC.md`, `../geoji-server/API.md`

## 준비물

dev 서버와 토큰이다. 토큰 절차는 `docs/release/RUNBOOK.md` 환경 변수 절이고 `.env.local`은 에이전트가 읽지 못하니 사용자가 채운다. 계정이 둘 필요한 TC는 두 번째 dev 서버를 다른 포트로 사용자가 띄운다.

```bash
VITE_DEV_ACCESS_TOKEN={두 번째 계정 토큰} pnpm dev --port 3801
```

없으면 그 TC는 확인불가다.

## 절차

1. 범위를 정한다. 요청이 화면이나 흐름을 지목하면 그 TC만, 아니면 전부
2. TC를 화면 단위로 묶는다
3. 화면마다 둘을 병렬로 부른다. `qa-verifier`에는 확인이 코드 대조인 TC와 화면 절을, `browser-runner`에는 확인이 브라우저인 TC와 포트를 넘긴다. 둘 다인 TC는 양쪽에 넘기고 한쪽이라도 실패면 실패다
4. 결과를 모아 TC 번호마다 통과, 실패, 확인불가 하나와 근거 한 줄을 낸다. 확인불가를 비워 두지 않는다
5. 실패는 `geoji-dev`로 넘긴다

## 에이전트

`.claude/agents/qa/`의 `tc-author`, `browser-runner`, `qa-verifier`다. `model`은 전부 opus다. 서브 에이전트로 부르고 결과는 반환값으로 받는다. 화면이 다르면 병렬로 불러도 되지만 browser-runner는 한 번에 하나만 부른다. 브라우저 도구를 둘이 나눠 쓰면 서로의 탭을 본다.

## 결과

`_workspace/qa/{날짜}/`에 TC마다 판정 파일과 스크린샷을 둔다. `.gitignore`에 있어 저장소 문서가 가리키면 안 된다. 요약은 응답으로 낸다.

```
| 번호 | 판정 | 근거 |

통과 n, 실패 n, 확인불가 n
실패 목록과 geoji-dev로 넘길 문구
확인불가를 이유별로 묶은 수
```

## 이어서 할 때

- 실패를 고친 뒤면 그 TC만 다시 돌린다
- 명세가 바뀌면 `tc-author`로 TC를 맞춘 뒤 바뀐 TC만 돌린다
- 남긴 결과 폴더가 있으면 먼저 읽고 판정이 바뀐 것만 보고한다

## 막혔을 때

- 에이전트가 실패하면 한 번 다시 부른다. 또 실패하면 그 화면을 확인불가로 적는다
- 브라우저 도구가 두세 번 응답하지 않으면 그 TC를 확인불가로 적고 다음 화면으로 간다
- 실패가 열 건을 넘으면 부류로 묶어 보고한다

## 미결정

| 무엇                                           | 누가 정하나 |
| ---------------------------------------------- | ----------- |
| 통과 기준. 한 단계가 실패하면 그 TC가 실패인가 | 프론트 둘   |
| 두 번째 계정 서버를 누가 어떻게 띄우나         | 프론트      |
| 결함을 어디에 등록하나                         | 팀          |

## 시나리오 둘

**정상.** "S-03 QA 돌려줘"가 온다. TC.md에서 S-03의 TC 다섯을 고른다. qa-verifier에 코드 대조 둘과 DESIGN-SPEC S-03 절을, browser-runner에 브라우저 넷과 포트 3800을 넘긴다. browser-runner가 빈 상태 TC를 확인불가로 낸다. 계정에 방이 이미 있어서다. 요약 표에 통과 셋, 확인불가 하나, 실패 하나를 적고 실패는 geoji-dev로 넘길 문구를 붙인다.

**막힘.** dev 서버가 없고 `.env.local`도 없다. 사용자에게 RUNBOOK 절차로 토큰을 채우고 서버를 띄워 달라고 하고 멈춘다. 코드 대조만 먼저 돌리지 않는다. 절반만 돈 결과는 통과처럼 읽힌다.

## 하지 않는 것

- 코드 수정과 커밋
- TC 없이 절차를 지어내 돌리기
- 배포 주소를 대상으로 삼기
- 기대를 채워 판정하기
