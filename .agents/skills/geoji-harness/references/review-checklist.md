# 검토 항목

`geoji-design-reviewer`와 `geoji-code-reviewer`가 읽는다. 자기 담당 절만 보면 된다.

지적에는 근거를 단다. 어느 문서의 어느 절이 무엇을 정했고 코드가 무엇을 했는지 둘 다 보인 뒤에 판정한다. 근거를 못 대면 지적이 아니라 취향이다.

## 디자인 검토

### 기계로 먼저 거른다

```bash
# 대괄호 임의값
grep -rnE 'class(Name)?="[^"]*\[' src/

# cn과 cva 안의 임의값. 위 검사에 안 걸린다
grep -rnE '"[^"]*\[[0-9]' src/

# 비워진 기본 팔레트. 숫자가 붙은 색은 CSS가 안 나온다
grep -rnE '(bg|text|border|ring|fill|stroke)-(gray|slate|zinc|neutral|stone|red|orange|amber|yellow|lime|green|emerald|teal|cyan|sky|blue|indigo|violet|purple|fuchsia|pink|rose)-[0-9]' src/

# 쓰지 않기로 한 다크 변형
grep -rn "dark:" src/
```

`red`와 `green`은 프로젝트 토큰이라 숫자 없이 쓴다. 세 번째 검사는 숫자가 붙은 것만 잡는다.

### 눈으로 본다

| 항목        | 무엇을                                                                                         |
| ----------- | ---------------------------------------------------------------------------------------------- |
| 빠진 요소   | 명세 배치 항목을 하나씩 코드에서 찾는다                                                        |
| 빠진 상태   | 로딩, 빈 목록, 오류, 비활성. 명세에 있는데 코드에 없으면 적는다                                |
| 색의 뜻     | 테라코타는 유죄와 기각과 수감, 경고. 그린은 무죄와 동의와 무지출. 노랑은 화면당 주요 액션 하나 |
| 카피        | 명세에 문구가 있으면 글자 그대로인지. 없는 문구를 지어냈는지                                   |
| 타이포 단계 | `theme/typography.css`의 `--text-*` 토큰을 썼는지. 토큰에 없는 크기만 기본 클래스를 쓰는지     |
| 토큰 추가   | `theme/`에 토큰을 더했으면 `cn.ts`의 `extendTailwindMerge`에도 넣었는지                        |

### 적지 않는 것

명세가 정하지 않은 여백과 순서를 다르게 하고 싶다는 것.

## 코드 검토

### 기계로 먼저 거른다

```bash
# features 사이의 import
grep -rnE "from ['\"](\.\./)+features/" src/features/

# shared가 위 층을 가져오는 것
grep -rnE "from ['\"](\.\./)+(app|features)/" src/shared/

# 쓰지 않기로 한 경로 별칭
grep -rn "from ['\"]@/" src/

# 배럴. features/{feature}/index.ts 하나만 있어야 한다
find src -name index.ts

# export * 금지
grep -rn "export \*" src/

# 넓힌 타입
grep -rnE ": *any\b|as +[A-Z]" src/
```

마지막 검사는 `Object.keys(VERDICT_LABELS) as Verdict[]`를 함께 잡는다. `Object.keys`가 `string[]`을 반환해 단언을 뺄 수 없는 자리라 지적하지 않는다. `import ... as Foo`도 걸리니 결과를 그대로 옮기지 말고 한 줄씩 본다.

### 눈으로 본다

| 항목      | 무엇을                                                                                       |
| --------- | -------------------------------------------------------------------------------------------- |
| 중복 구현 | 새로 만든 것이 `src/shared/`에 이미 있는지. 이름이 달라도 하는 일이 같으면 중복              |
| 파생 상태 | 다른 상태에서 계산할 수 있는 값을 따로 들고 있는지. 두 값이 어긋나는 순간이 생긴다           |
| effect    | 렌더 중에 계산할 수 있는 것을 `useEffect`로 미뤘는지. 한 번 더 그린다                        |
| props 폭  | 실제로 쓰는 것보다 넓게 받는지                                                               |
| 파일 이름 | 컴포넌트는 PascalCase, 그 외는 camelCase, 폴더는 kebab-case                                  |
| 공개 API  | `features/{feature}/index.ts`가 밖에서 실제로 쓰는 것만 내보내는지. 타입은 `export type`인지 |

### 접근성

| 항목            | 무엇을                                                                        |
| --------------- | ----------------------------------------------------------------------------- |
| 누를 수 있는 것 | `div`에 `onClick`을 걸지 않았는지. `button`에 `type`이 있는지                 |
| 아이콘 버튼     | 글자 없이 아이콘만 있으면 `aria-label`이 있는지                               |
| 장식 아이콘     | 뜻이 없는 아이콘에 `aria-hidden="true"`가 있는지                              |
| 폼              | 입력에 라벨이 연결됐는지. `label`로 감싸거나 `htmlFor`로 잇는다               |
| 상태 표시       | 고른 상태를 색으로만 알리지 않는지. `aria-pressed`나 `aria-selected`가 있는지 |
| 목록            | `key`에 배열 인덱스를 쓰지 않았는지                                           |

### 적지 않는 것

동작이 틀린 것. 그것은 게이트와 브라우저로 잡는다. 여기서는 구조가 규칙을 지켰는지, 나중에 고치기 어렵게 만들지 않았는지 본다.

## 심각도

| 심각도 | 무엇                                                                                       |
| ------ | ------------------------------------------------------------------------------------------ |
| 높음   | 화면이 깨지거나 규칙을 어겼다. 대괄호 임의값, 비워진 팔레트, import 방향 위반, 접근성 누락 |
| 보통   | 명세와 다르다. 빠진 상태, 다른 문구, 중복 구현                                             |
| 낮음   | 지금 틀린 것은 없지만 나중에 걸린다                                                        |
