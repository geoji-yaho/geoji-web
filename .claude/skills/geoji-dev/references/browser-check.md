# 브라우저 확인

qa-verifier가 요청받았거나 화면이 새로 생겼을 때 읽는다. 게이트와 경계면 대조를 먼저 끝낸 뒤다.

## 개발 서버

포트는 3800이다. 떠 있으면 그대로 쓰고 끝나도 내리지 않는다. 사용자가 띄운 것일 수 있다.

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3800/
```

없으면 `pnpm dev`를 백그라운드로 띄우고 응답할 때까지 조건을 걸어 기다린다. 자기가 띄운 서버는 끝나면 내린다. 개발 서버의 base는 `/`이고 빌드만 `/geoji-web/`이다. 서버를 부르는 화면은 `VITE_API_BASE_URL`이 있어야 열리고 토큰이 없으면 401로 `/login`에 간다. 그 이동 자체가 401 처리의 확인이다.

## 도구

Playwright MCP를 쓴다. `mcp__playwright__browser_navigate`로 열고 `browser_snapshot`으로 구조를, `browser_take_screenshot`으로 실제 화면을, `browser_console_messages`와 `browser_network_requests`로 콘솔과 요청을 본다. 끝나면 `browser_close`로 닫는다.

## 확인 순서

1. 화면을 연다. 명세의 배치 항목이 실제로 보이는지 본다. DOM에 있는 것과 눈에 보이는 것은 다르다. 색 토큰이 빠지면 요소는 있는데 배경과 글자가 같은 색이 된다
2. 콘솔을 읽는다. React 경고를 그냥 두지 않는다. key 누락, 제어와 비제어 전환, 없는 prop 전달이 자주 나온다. 토큰 없이 받은 401 응답 로그는 정상이다
3. 폭을 바꾼다. `browser_resize`로 360과 393에서 가로 스크롤이 생기는지 본다
4. 상태를 본다. 명세에 상태가 여럿이면 각각 확인한다. 빈 목록, 로딩, 실패, 투표 중과 판결 완료, 비활성

## 다이얼로그를 부르지 않는다

`alert`와 `confirm`은 브라우저를 멈추게 한다. 그런 것을 부를 수 있는 버튼을 누르지 않는다. 실수로 띄웠으면 사용자가 직접 닫아야 한다고 알린다.

## 막히면

도구가 두세 번 실패하거나 응답이 없으면 더 시도하지 않는다. 무엇을 시도했고 어디서 막혔는지 적어 넘긴다. 확인하지 못한 것을 통과로 적지 않는다.
