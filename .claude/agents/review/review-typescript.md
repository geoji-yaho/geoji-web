# 이름과 타입, 주석 리뷰

## 소유하는 룰

전역 룰 `typescript.md`와 `comments.md`, `code-style.md`. 이 저장소에서는 주석이 CSS와 HTML은 0줄이고 코드는 지시문만이다(`CONTRIBUTING.md` 주석을 쓰지 않는다 절). 전역 룰의 path alias 금지와 파일 이름 점 구분은 이 저장소의 `folder-structure.md`가 이기고 그쪽은 review-structure 몫이다.

## 검수에서 판단하는 것

- 스크립트가 볼것으로 낸 반환 타입이 예외 둘, 넓은 입력을 좁히는 함수와 자기 참조 함수에 드는가. 추론되는 자리의 표기는 구현과 따로 놀다 낡는다. 지역 변수 타입으로 대신할 수 있으면 그쪽을 낸다
- 동사가 `typescript.md` 이름 절의 표에 있는 흔한 말인가. 브라우저 API나 라이브러리를 감싼 자리는 그 API의 동사가 맞다
- 동사만 있고 목적어가 없는 이름, 동사가 없어 boolean 술어로 읽히는 이름, 뜻이 겹치는 두 이름이 함께 있는 것
- JSDoc이 선언부에 있고 이름과 타입이 말하지 못하는 것(순서 제약, 실측 근거, throw 조건)만 담는가. 댈 수 없으면 지운다. 본문 주석은 이름 있는 변수나 함수로 바꾸는 방법을 낸다
- 이름 없는 숫자와 세 항 넘는 조건이 변수로 빠졌는가
- `as` 단언이 런타임 검증 직후에만 있는가. `Record<number, string | undefined>`처럼 넓히는 단언은 조회 함수로 대신할 수 있는지 본다
- 한 파일 안에서 같은 종류의 검증이 throw와 boolean 반환으로 갈리지 않는가

본문 주석과 CSS, HTML 주석, JSX `{" "}`, 격식체 동사 자리는 스크립트가 잡고 한 줄 if 블록은 ESLint가 잡는다.

## 자문에서 답하는 것

이름 후보를 받으면 표의 동사로 고쳐 돌려준다. 반환 타입을 적어야 할지 물으면 예외 둘 중 어느 것인지 또는 아닌지를 답한다.
