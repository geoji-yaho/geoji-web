# 떼거지 테스트 케이스

## 이 문서

화면마다 어떤 단계를 밟으면 무엇이 보여야 하는지 적는다. 원천은 명세다. 화면과 흐름은 `../design/DESIGN-SPEC.md`, 동작 규칙과 확인 필요 항목은 `../product/SPEC.md`, API 연동 현황은 `../product/ROADMAP.md`를 따른다. 코드는 원천이 아니다. 코드를 보고 쓴 케이스는 코드가 맞다고 확인해 줄 뿐 어긋난 자리를 잡지 못한다.

**번호.** `TC-S{화면 두 자리}-{두 자리}`다. 화면 번호는 화면 목록의 ID를 쓴다. 한 번 붙인 번호는 바꾸지 않고 지운 번호는 다시 쓰지 않는다. 케이스를 더할 때는 그 화면의 마지막 번호 다음을 쓴다.

**판정.** 셋 중 하나로 적는다.

| 판정     | 언제                                                                    |
| -------- | ----------------------------------------------------------------------- |
| 통과     | 기대에 적힌 것이 그대로 보인다                                          |
| 실패     | 기대와 다른 것이 보인다. 무엇이 보였는지 함께 적는다                    |
| 확인불가 | 연동 전이거나 미결정이라 단계를 끝까지 밟을 수 없다. 사유를 함께 적는다 |

**실행 전제.** `pnpm dev`로 3800 포트 개발 서버를 띄운다. API를 부르는 화면은 `.env.local`의 `VITE_API_BASE_URL`과 `VITE_DEV_ACCESS_TOKEN`이 있어야 하고, 값을 넣는 방법은 `RUNBOOK.md`의 환경 변수 절에 있다. 토큰은 한 시간 뒤 만료된다. 계정이 둘 필요한 케이스는 계정 A와 계정 B로 적고 단계마다 어느 계정인지 밝힌다.

**확인 칸.** 브라우저는 개발 서버에서 눈으로 밟는 것, 코드 대조는 재시도 횟수나 상태 코드 분기처럼 눈에 보이지 않는 규칙, 둘 다는 화면도 보고 규칙도 맞춰 보는 것이다.

**연동 칸.** `ROADMAP.md`의 API 연동 현황 표를 기준으로 됨과 전을 가른다. 전이면 기대를 화면 표시까지만 적었고 저장과 갱신은 적지 않았다. 연동된 엔드포인트가 있는 화면이라도 그 케이스가 다루는 값이 응답에 없으면 전으로 적었다.

- 기대: 현재 예산과 새 금액 입력, "이번 달 예산은 다음 달까지 다시 바꿀 수 없습니다" 안내, 변경하기 버튼이 보인다

### TC-S13-02 이번 달에 이미 바꿨으면 버튼이 비활성이다

- 흐름: 예산 변경
- 전제: 이번 달에 예산을 한 번 바꾼 계정. `SPEC.md` 확인 필요 절의 "예산 변경 비활성 문구" 행에 걸린다. 화면 명세와 코드의 문구가 조사만 다르다

- 기대: 안내 문구 자리가 이번 달에 이미 변경했고 다음 달 1일부터 다시 바꿀 수 있다는 문구로 바뀌고 변경하기 버튼이 비활성이다. 문구는 어느 쪽으로도 단정하지 않는다
- 확인: 브라우저
- 연동: 전

### TC-S13-03 변경하기를 누르면 마이페이지로 돌아간다

- 흐름: 예산 변경
- 전제: 이번 달에 아직 바꾸지 않은 계정. 새 금액을 입력한 상태
- 단계: 1. 변경하기를 누른다
- 기대: 마이페이지 `/me`로 돌아가고 이번 달 요약의 예산이 새 금액으로 보인다
