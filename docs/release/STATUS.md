## 서버가 막고 있는 것

프론트가 만들 수 없는 것이다. 근거는 2026-09-19 18:35에 배포 API를 직접 찔러 확인했다.

| 기능             | 화면             | 막는 것                                                               |
| ---------------- | ---------------- | --------------------------------------------------------------------- |
| 무지출 신고      | S-03, S-06       | `/no-spend`가 404다. `NoSpendCard`만 있고 쓰는 화면이 없다            |
| 이모지 리액션    | S-06, S-10       | `/reactions`가 404다                                                  |
| 형 집행 추적     | S-03, S-06, S-10 | 판결 응답 `view`에 형 시작과 종료 시각이 없다                         |
| 랭킹 두 축       | S-07             | 무지출왕과 잔소리왕 집계가 없다. 지금은 거지력 순만 그린다            |
| 피드 무한 스크롤 | S-06             | `?cursor=`를 붙여도 무시되고 최신 100건을 그대로 준다                 |
| 피드 댓글 수     | S-06             | 피드 응답에 `commentCount`가 없어 게시물마다 댓글을 따로 부른다       |
| 솔직 팝업        | S-09b            | AI 심문관이 `intakeSource: "FALLBACK"`, `status: "PASS"`로만 온다     |
| 이미지 첨부      | S-09             | 업로드 엔드포인트가 없다. `AttachmentField`를 등록 폼에 붙이지 않았다 |
| Web Push         | 전체             | VAPID 키와 발송 엔드포인트가 없다                                     |

판결 짤도 다르다. 2026-09-19 21시대에 확정 게시물 6건을 판결 조회로 확인했고 6건 다 `view.meme`이 채워져 왔다. 이미지 URL도 200으로 받아진다. 18:35 확인 때는 `null`이었다. 피드 조회 응답에는 `view` 필드 자체가 없어 게시물마다 판결 조회를 따로 불러야 나온다.

AI 판사는 다르다. 실제로 돌고 판결 5건 중 3건이 `view.source: "AI"`로 왔다. 나머지 2건은 템플릿으로 떨어졌고 재시도 마감 90초가 지나도 올라오지 않는다.

데모용 AI 배심원은 9/20에 붙였고 위 측정에는 들어 있지 않다. 방 정보와 초대 시트의 "데모용 AI 유저 추가" 버튼이 `POST /api/rooms/{roomId}/ai-member`를 부르고 서버 코드는 geoji-server `ec5024e`에 있다. 운영에는 봇 계정과 환경 변수가 더 필요해 배포에서 확인하지 못했다. 반영 전에는 `AI_JUROR_NOT_CONFIGURED`가 오고 화면이 "지금은 추가할 수 없어요"를 보인다.

| 이용약관              | 문서가 없어 로그인 화면에서 링크를 뺐다. 개인정보처리방침만 남겼다. 문서가 생기면 같은 자리에 되살린다                                                                                      |

## 뒤로 가기 스크롤 복원

재현된다. 배포와 개발 서버 둘 다에서 같다.

1. 방 피드를 `window.scrollTo(0, 900)`으로 내린다. `window.scrollY`가 837이 된다
2. 판결문 보기를 눌러 판결 화면으로 간다
3. 뒤로 가면 피드 문서 높이는 1689로 돌아오는데 `scrollY`는 0이다

`window.scrollTo`를 가로채 보면 뒤로 가는 순간 `scrollTo(0, 0)` 한 번만 불리고 `scrollTo(0, 837)`은 불리지 않는다. react-router 8.3.1의 복원 이펙트는 저장값이 숫자일 때만 그 값으로 옮기고 아니면 맨 위로 보내므로, 저장이 되지 않았다는 뜻이다.

아닌 것으로 확인한 것이다.

| 의심한 것                          | 결과                                             |
| ---------------------------------- | ------------------------------------------------ |
| `AnimatePresence`의 `mode="wait"`  | 빼도 같다                                        |
| `location.key`가 바뀐다            | `getKey`를 `location.pathname`으로 고정해도 같다 |
| 문서 높이가 줄어 브라우저가 깎는다 | 초기화되는 순간 문서 높이가 1689로 그대로다      |
| `StrictMode`의 이펙트 두 번 실행   | 배포 빌드에서도 같다                             |

`sessionStorage`의 `react-router-scroll-positions`가 전부 0인데, 이 값은 페이지를 떠날 때만 쓰이므로 메모리에 있던 값이 그때 이미 0이었다는 뜻이다. 저장은 `startNavigation`이 시작할 때 `window.scrollY`를 읽는데 그 시점에는 837이어야 한다. 여기서 막혔다.

임시로 타이머를 걸어 복원하는 방법은 쓰지 않았다. 원인을 모르는 채 덮으면 다른 자리에서 다시 나온다.
