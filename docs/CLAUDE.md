# docs 안내

## 배치 기준

만드는 것은 `product/`, 보이는 것은 `design/`, 내보내고 운영하는 것은 `release/`다. 새 내용은 기존 파일의 절로 먼저 넣고, 파일이 길어져 찾기 어렵거나 읽는 사람이 달라지면 그때 분리해 아래 표에 한 줄 더한다.

| 파일                    | 답하는 질문                                 |
| ----------------------- | ------------------------------------------- |
| `product/PRD.md`        | 누구의 어떤 문제를 왜 푸는가                |
| `product/SPEC.md`       | 각 기능이 정확히 어떻게 동작하는가          |
| `product/ROADMAP.md`    | 무엇을 어떤 순서로 만드는가. 뺀 것과 미결정 |
| `design/DESIGN.md`      | 서비스가 어떤 인상을 주는가. 토큰과 카피 톤 |
| `design/DESIGN-SPEC.md` | 각 화면에 무엇이 어떻게 놓이는가            |
| `release/RUNBOOK.md`    | 배포와 장애 대응, 운영 절차를 어떻게 하는가 |
| `release/PRIVACY.md`    | 어떤 정보를 모으고 어떻게 다루는가          |

## 한 정보 한 자리

같은 내용을 두 문서에 적지 않는다. 서비스 정의는 `PRD.md`에만 두고 다른 문서는 한 줄 정의만 적는다. 뺀 것과 미결정은 `ROADMAP.md`에만, 위키와 코드가 어긋나는 것은 `SPEC.md`의 확인 필요 절에만 두고 다른 문서는 그리로 보낸다. 아직 못 채우는 절은 무엇을 언제 채우는지 한 줄만 남긴다.
