# 떼거지 PRD

만들기 전에 무엇을 왜 만드는지 합의하는 문서다. 기준은 팀 위키다. 범위가 바뀌면 코드보다 이 문서를 먼저 고친다.

## 한 줄 정의

친구들이 내 지출을 재판하는 소비 절제 커뮤니티. 사용자는 피고이고 같은 방 친구들은 배심원이며 AI가 판사다. 지출은 두 종류로 올린다. 돈 썼어요는 지출 뒤에 올려 유죄 또는 무죄를 받고 유죄면 형량이 붙는다. 살까 말까는 지출 전에 올려 동의 또는 기각을 받는다. 배심원 투표가 끝나면 AI 판사가 최종 판결과 판결문을 낸다.

## 문제

카톡 거지방이 흥한 이유는 절약 기능이 아니라 여러 명에게 혼나는 재미였다. 그런데 채팅방은 대화가 흘러가고 누가 얼마나 아꼈는지 남지 않는다. 사람이 직접 반응해 줘야 굴러가서 방이 식으면 챌린지도 끝난다. 혼자 하는 절약은 감시자가 없어 오래가지 않고 가계부 앱은 기록은 시키지만 절제는 시키지 못한다.

떼거지는 이 재미를 재판 구조로 옮긴다. 놀리고 혼내는 조리돌림은 사람(배심원)이 맡고 AI 판사는 그 평결 위에서 양형과 판결문을 쓴다. 판결과 등급, 랭킹이 누적되는 기록으로 남는다.

## 사용자

지출을 줄이고 싶은데 혼자서는 못 참는 사람이다. 이미 친구인 소그룹이 방을 만들어 서로의 지출을 구경하고 놀리면서 함께 아낀다.

| 구분      | 내용                                                                                   |
| --------- | -------------------------------------------------------------------------------------- |
| 1차 대상  | 20대와 30대. 배달, 택시, 카페 같은 소액 충동 소비를 줄이고 싶지만 혼자서는 실패한 사람 |
| 사용 맥락 | 이미 친구인 3명에서 8명 소그룹. 방 정원은 최대 20명                                    |
| 쓰는 시점 | 지출 직전(살까 말까)과 지출 직후(변론). 하루 1회에서 3회, 짧게                         |
| 역할      | 자기 지출에서는 피고, 남의 지출에서는 배심원                                           |

## 핵심 가치

- **평결은 친구가, 선고는 AI가.** 배심원 투표가 다수결로 결과를 정하고 AI는 이를 뒤집을 수 없다. AI 판사는 그 위에서 양형과 판결문, 짤을 정한다. AI가 판결의 주체로 드러나면서도 친구들의 투표가 무시당하는 느낌은 생기지 않는다
- **판결은 혼자 받지 않는다.** 판결 한마디에 투표와 댓글, 리액션이 함께 쌓이는 피드. 거지방이 흥한 이유를 구조로 옮긴 것이다
- **자진 신고.** 계좌와 카드를 연동하지 않고 지출을 스스로 올린다. 무지출도 "오늘 0원 썼어요" 버튼으로 직접 선언해야 기록된다
- **잔소리 톤이 핵심 재미.** 판결 문구가 딱딱하면 죽는다. 방장이 잔소리 강도를 순한맛, 매운맛, 지옥맛 중에서 고른다
- **판결은 도장으로 찍힌다.** 결과 페이지에서 도장이 내려와 찍히는 애니메이션과 효과음이 붙고 피드와 공유 카드에는 찍힌 자국이 남는다
- **바이럴 통로는 판결 카드.** 정사각형 공유 카드에 판결 짤이 면적의 절반 이상 들어간다

## 범위

화면 14개가 하단 탭바 없이 홈에서 들어가는 2단계 구조로 놓인다. 화면 목록과 구성은 `../design/DESIGN-SPEC.md`, 동작 규칙은 `SPEC.md`에 있다.

| 게시물    | 시점    | 배심원 선택지  | 확정 뒤                                                    |
| --------- | ------- | -------------- | ---------------------------------------------------------- |
| 돈 썼어요 | 지출 후 | 유죄 또는 무죄 | 유죄면 AI 판사가 형량(집행유예, 징역 1일, 무기징역)을 선고 |
| 살까 말까 | 지출 전 | 동의 또는 기각 | 형량 없음. 판결문과 짤만                                   |

표가 2개 미만이면 각하되어 AI 선고가 없다. 결과는 유죄, 무죄, 동의, 기각, 각하 다섯 가지이고 전부 도장으로 표현한다.

명시적으로 뺀 것은 채팅, 이의신청(재심), 24시간 재알림, 소비 방어 금액, 무지출 최장기록, 네이티브 앱, 카드와 계좌 연동, 방 대항전, AI 소비탐정, 전과 기록 페이지, 공개 방, 대댓글, 다크모드, 구글과 Apple 로그인이다. 이유와 날짜는 `ROADMAP.md`의 하지 않기로 한 것 표에 있다. 확장 기능(거지방 실록, 소비 탐정, 전과와 모범수, AI 항소심)은 만들지 않고 발표 자료에서 확장성으로 다룬다.

## 성공 기준

1차 목표는 예선 통과(TOP20)다. 예선은 내부 심사 80%에 온라인 투표 20%이고 기준 4개 중 3개가 기획 영역이다.

| 예선 기준      | 이 서비스의 답                                                                                                                |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 기획력         | 거지방의 재미를 재판 구조로 옮겼다. 30초 안에 설명이 된다                                                                     |
| 실현 가능성    | 화면 14개, 자진 신고, 룰 베이스 점수. 9/20까지 동작하는 PWA                                                                   |
| 확장성         | 거지방 실록, 소비 탐정, 전과와 모범수, AI 항소심을 발표에서 다룬다                                                            |
| AI 활용 적절성 | AI가 판사다. 양형과 판결문, 짤 선택을 AI가 하고 평결은 사람이 한다. 판결문 톤이 서비스의 재미이므로 AI를 빼면 성립하지 않는다 |

제출 폼의 필수 기재 4항목은 지금 써진다.

| 항목               | 답                                                                                                   |
| ------------------ | ---------------------------------------------------------------------------------------------------- |
| 배포된 서비스 링크 | 프론트엔드는 https://geoji-yaho.github.io/geoji-web/ 에 배포 중. 백엔드 주소는 규민이 스택을 정한 뒤 |
| 해결하려는 문제    | 위 문제 절                                                                                           |
| AI 활용 방식       | AI 판사가 배심원 평결 위에서 양형과 판결문, 짤을 정한다. 솔직 팝업으로 애매한 항목명을 되묻는다      |
| 사용한 AI 도구명   | Claude Haiku 4.5 기본, 품질이 부족하면 Sonnet 5                                                      |

P0는 심사 기간 링크 생존이다. 9/20 배포 동결 뒤 핫픽스만 허용한다. 서비스 지표는 기획서 v1.1의 제안값으로 무지출 신고율 40%(참여자의 주 1회 이상 신고), 정족수 충족률 80%, AI 판결문 폴백률 5% 이하다.

미결정 항목은 `ROADMAP.md`, 위키와 코드가 어긋나는 것은 `SPEC.md`의 확인 필요 절에 있다.
