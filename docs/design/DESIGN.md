# 떼거지 디자인 방향

서비스가 주는 인상과 그것을 만드는 규칙을 적는다. 화면별 상세는 DESIGN-SPEC.md에 적는다.

기준은 팀 위키의 서비스 설계 문서(9/2 디자인 방향 확정 절)와 디자인 v3 원본의 토큰 표다. 코드의 토큰 정본은 `src/shared/styles/globals.css`이고 지금 값은 시안을 눈으로 옮긴 근사값이다. 이 문서의 색 표에서 확인 필요로 표시한 칸이 교체 대상이다.

## 인상

크림색 바탕에 조선 엽전 컨셉. 로고는 귀엽게, 판결은 맵게. 2026-09-01 2차 회의에서 파란색을 버리고 이 방향으로 돌아섰고(혜준 시안), 2026-09-02 Claude Design 시안 D로 구체화됐다.

시안 D의 인상은 네 가지로 요약된다.

- 크림 바탕에 테두리 없는 카드. 한지 텍스처와 붓글씨는 뺐다
- 판결 5종(유죄, 무죄, 동의, 기각, 각하)은 테라코타와 그린의 낙관 도장으로 찍힌다
- 주요 액션 하나에만 노랑 CTA를 쓴다
- 시스템 고딕에 굵기로만 위계를 준다

하이파이는 A, B, C 세 안을 거쳐 D로 왔다. C의 낙관 도장에 A의 고딕 본문과 카드 위계를 합치고(혜준), 직각과 원색과 밀도를 덜어내 크림과 pill과 노랑 CTA 하나로 정리했다(규민). 찬규가 이 방향으로 확정했다(2026-09-02).

시안 A, B, C는 Claude Design 안에서 archive로 옮겼다. 시안 링크는 DESIGN-SPEC.md의 시안 목록에 있다.

## 카피 톤 가이드

거지방 감성이다. 존댓말인데 신랄하고, 구체적 환산으로 찌른다. 판결 문구가 핵심 재미 요소라 딱딱하면 죽는다.

예문은 전부 와이어프레임 v2 원문이다. 결과 이름(기각, 승인, 칭송)은 판결 3종 시절의 것이고 지금 결과는 5종(유죄, 무죄, 동의, 기각, 각하)이다. 톤의 기준으로만 쓴다.

- 기각: "지하철이 있었잖아요. 알람을 12개 맞추세요. 12,000원이면 편의점 도시락이 두 개입니다. 반성문 기대하겠습니다."
- 승인: "밥은 먹어야죠. 다만 곱빼기는 사치였습니다."
- 칭송: "3일 연속 무지출. 이 방의 유일한 희망입니다."

2026-09-03 혜준 피드백으로 더해진 문구.

- 배심원 사유 프리셋 칩(S-14): "지하철이 있었잖아요", "라면은 900원", "이건 인정", "다음엔 도시락"
- 솔직 팝업(S-09b): 화자는 AI 판사. "저기요. 그럴싸한 이름 붙이지 마시고 솔직히 얘기하세요." 강도(순한맛, 매운맛, 지옥맛)별 어미 변화는 미결정

시안 D의 판결문 본문 예문은 "밥이 없었다는 건 변론이 아니라 자백입니다."이다. 시안 헤드라인 "네 이놈!"은 사극 어미라 이 가이드(존댓말인데 신랄)와 어긋난다. 사극 어미를 채택할지는 미결정이고 찬규가 정한다.

코드에만 있는 토큰은 `--color-terracotta-soft`(#f6e2da / #3a2620)와 `--color-praise-soft`(#e6f2e9 / #1c2e21)다. 시안에는 이 이름의 틴트 토큰이 없다. 시안의 소프트 필은 fill 하나이고 무지출 카드는 그린 틴트라고만 적혀 있다. 코드에 남길지 fill로 합칠지는 토큰 교체 때 정한다.

색의 역할 규칙은 이렇다.

- 테라코타는 유죄와 기각과 수감에만 쓴다
- 그린은 무죄와 동의와 무지출에만 쓴다
- 각하 도장은 회색이다. 시안에 전용 토큰은 없다
- 탠은 아바타와 티어에 쓴다
- 노랑 CTA는 화면에서 주요 액션 하나에만 쓴다. FAB와 고정 CTA가 그 자리다

## 타이포그래피

시스템 고딕(Pretendard 폴백)이고 굵기로만 위계를 준다. 웹폰트를 로드하지 않는다. 붓글씨와 한지 텍스처는 시안 D에서 뺐다.

| 단계     | 크기 / 굵기 | 비고        | 쓰는 곳               |
| -------- | ----------- | ----------- | --------------------- |
| Display  | 38 / 900    |             | 워드마크 떼거지       |
| Amount   | 44 / 900    |             | 금액 입력과 금액 표시 |
| Headline | 26 / 900    |             | 판결 결과 헤드라인    |
| Title    | 18 / 900    |             | 화면 제목, 헤더       |
| Body     | 14 / 400    | 행간 1.7    | 본문, 판결문          |
| Label    | 11 / 800    | 자간 0.06em | 라벨, 태그            |

워드마크는 고딕 900으로 "떼거지"를 쓴다. 혜준의 로고 SVG에 든 가로형 워드마크는 아직 "거지방 / AI 가계부"이고 Pretendard에 의존한다. 브랜드 에셋 시안은 워드마크를 텍스트로 직접 그렸다. 배포용으로 확정되면 텍스트를 패스로 아웃라인 처리한다(로고 README 지시).

코드는 Tailwind 기본 시스템 글꼴 스택을 그대로 쓴다. 위 여섯 단계를 토큰으로 정의한 것은 아직 없다.

## 형태

- 카드는 테두리 없이 라운드 22에서 24. 텍스트 필드는 카드색에 라운드 16
- 버튼과 칩과 세그먼트는 pill. 뒤로가기 버튼은 36 원형 필
- 도장은 한 변의 1/8 라운드. 크기는 피드 카드 소형 54, 판결 결과 대형 96
- 바텀시트는 화면 바탕색, 상단 라운드 24, 핸들 40 x 4, 배경 딤 45%
- FAB는 52 높이의 pill로 오른쪽 아래. 고정 CTA는 좌우 20 여백에 높이 44
- 빈 상태는 로고 56에 제목 15 / 900과 설명 두 줄. 카드 안 가운데 정렬(가운데 정렬은 빈 상태만 예외)

### 판결 도장

판결 결과 5종은 뱃지가 아니라 낙관 도장이다. 유죄와 기각은 테라코타, 무죄와 동의는 그린, 각하는 회색이다.

애니메이션은 2026-09-02 카톡에서 찬규가 내고 소윤이 동의한 결정이다.

- 판결 결과 페이지(S-10)에 처음 들어오면 도장이 위에서 내려와 "탁" 찍히고 효과음("두둥탁")이 같이 난다. 찍힌 뒤에는 살짝 기울어진 도장 자국으로 남는다. 찍히기 전과 찍힌 후 두 상태가 있고 헤더 오른쪽에 사운드 끄기 토글을 둔다
- 피드 카드(S-06)와 공유 카드(S-11)에서는 찍힌 도장 자국으로만 보인다. 다만 피드에서 판결이 막 확정된 카드를 처음 볼 때는 소형 도장이 찍히는 짧은 애니메이션이 한 번 재생된다

도장 형태는 미결정이다. 혜준이 2026-09-03 디스코드에 원형, 결재형, 인장형(망치 아이콘) 시안을 올렸고 현재 디자인은 정사각 인장형을 유지한다. 디자인 확정 전에 정한다.

코드의 `VerdictStamp`는 정사각 인장형에 가깝게 6도 기울인 사각 도장이고 색은 테라코타와 그린 둘뿐이다. 각하 회색과 애니메이션은 아직 없다.

## 로고와 앱 아이콘

혜준이 2026-09-02 디스코드에 올린 주머니 시리즈 3종(P1 기운 주머니, P2 주머니 마스코트, P3 엽전 주머니) 중 P3 엽전 주머니를 쓴다. 주머니에서 네모 구멍 엽전이 튀어나오는 모양이고, 회의 컨셉(크림색과 조선 엽전)에 가장 가깝다. 2026-09-02 디자인 확정에 로고 P3가 함께 들어갔다. 다만 팀 위키 결정 로그의 미결정 표에는 로고 시안 선택이 팀 결정으로 남아 있다. 확인 필요.

저장소에는 아직 로고 SVG가 없고 홈 헤더는 로고 자리에 이모지를 임시로 둔다. 로고 파일 종류와 주머니 팔레트는 팀 위키의 로고 시안 문서에 있다.

앱 아이콘 규칙은 브랜드 에셋 시안 기준이다.

| 모양      | 1024 기준, iOS 22.4% 라운드                                       |

## 반응형

모바일 세로가 기준이다. 화면 폭은 미결정이다. 와이어프레임은 360 x 800, 하이파이와 공통 컴포넌트는 393(콘텐츠 폭 353, 좌우 20)으로 만들어져 서로 다르다. 360과 393 중 하나로 맞추는 결정은 찬규가 한다.

태블릿과 PC 폭의 배치는 위키에 없다. 코드는 본문을 `max-w-md`로 가운데 정렬할 뿐 따로 정한 것이 없다.

## 다크모드

위키 문서끼리 어긋난다. MVP 스펙은 다크모드를 명시적으로 뺀 것 목록에 넣었다. 서비스 설계와 결정 로그와 디자인 v3는 다크 팔레트(딥 브라운 #120d0b와 #2a1f1a, 골드 #EFC24F)를 라이트와 병행한다고 적었다. 확인 필요. 코드는 `prefers-color-scheme`로 다크 값 일부를 정의해 둔 상태다.

## 코드 규칙

- 색과 간격, 모서리 값은 `src/shared/styles/globals.css`의 `@theme` 토큰으로 정의하고 `p-[18px]` 같은 임의값을 클래스에 직접 박지 않는다
- 지금 컴포넌트에 남아 있는 임의값은 토큰 교체 때 함께 옮긴다. `AmountField`의 `text-[44px]`, `EmptyState`의 `text-[56px]`와 `text-[15px]`, `Fab`의 `h-[52px]`, `VerdictStamp`의 `size-[54px]`와 `rotate-[-6deg]`다
- `VerdictTag`의 승인 스타일은 Tailwind 기본 회색(`gray-100`, `gray-600`)을 쓴다. 판결 3종 타입과 함께 정리한다

디자인 미결정(화면 폭, 사극 어미, 도장 형태, 로고 선택, 도메인)은 `../product/ROADMAP.md`의 미결정 절, 코드와 위키의 불일치(토큰 hex, `Verdict` 타입, 다크모드)는 `../product/SPEC.md`의 확인 필요 절에 모아 둔다. 이 문서는 각 절에서 해당 자리에만 표시한다.
